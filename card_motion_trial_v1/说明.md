# C04 信息卡动效试样

本次只试做“保存的是可继续编辑的结构”这一张卡。全部试验、渲染和检查文件位于 V5；V4 只读。此目录是单卡试验包，并非完整工程迁移，也没有切换到 AE。

- `exports/C04_upgraded_with_audio.mp4`：新版原尺寸样片。

## 变化范围

仅改 `episode/06_project/cards/scene.js` 中的 C04 函数。保留原始标题、图层名、结论和底注；保留深绿/纸白面板、字体、最终坐标、原音轨和每个事件的起止帧。

1. 保存与打开：同样的三层结构副本沿同一 SVG 曲线往返，按真实弧长移动，加入受控加减速和接收动作。保存期间源编辑结构保留，关闭后右侧工程文件保留。
2. 关闭与恢复：用局部遮罩收拢内容，再按顺序展开画面和图层；恢复前清退“已关闭”，避免残字。
3. 图层结构：图层短暂分离后归位。
4. 对象位置：在原位置描出定位线；这一段对象不移动。
5. 继续编辑：光标带主体小幅移动 32 像素，再回到原位置。

上述曲线与动作是这次单卡的实现选择，没有写入通用参数、制作规则或 SOP。仍使用原来的 HTML/SVG → Chrome 逐帧 → FFmpeg 渲染链，`card_kit.js`、`render_cards.py`、`cards.json`、`effective_defaults.json` 和标准锁均保留原样。没有新增第三方依赖。

## 可编辑源文件与重渲染

`C04_motion.js` 是可读的动作实现；`baseline` 保存未改动的参考输入；`episode` 是试验副本，仅收集了渲染 C04 所需素材。不要在这个精简包里执行全片或其他卡的渲染。

在本目录打开 PowerShell，使用本机已有 Python、Playwright、Chrome、Pillow、NumPy 与 FFmpeg：

```powershell
python -B .\apply_motion.py
python -B .\episode\06_project\cards\render_cards.py --cards C04 --workers 1
python -B .\package_preview.py
```

`apply_motion.py` 仅把独立 C04 实现写入 V5 的场景副本。修改动作后运行上述命令即可生成新的样片。现有配置保留本机字体与 `D:\ffmpeg\bin\ffmpeg.exe` 路径。`prepare_trial.py` 是本次一次性复制工具，已有输入时会拒绝覆盖，无需再次运行。

## 验证与限制

- 渲染器检查 7 个过程的 20%/50%/80% 采样、编码中点及前后帧、字框越界、随机取帧确定性、视频帧数、解码和色彩标签。证据在 `episode/08_qc/cards/C04`。
- `checks/motion_verification.json` 验证两个阅读区间共 92 帧静止，文案一致，乱序取帧一致。原版和新版静止画面仅 39 个圆角边缘像素出现最大 1/255 的浏览器抗锯齿差异，布局与绘图颜色未改；检查容限记录在报告中。
- `qc/source_snapshot.json` 与 `qc/scope_verification_final.json` 记录 V4 的文件清单、关键内容哈希和试验允许变化范围。最终核对 12,254 个文件的路径、大小、修改时间以及 64 项关键内容哈希，均未改变；标准入口原有的 54 项哈希全部匹配。V5 的 9 个源码输入中仅 `scene.js` 的 C04 区间改变。
- `exports/preview_check.json` 记录交付视频与原音频片段的检查结果。
- 已审看过程关键帧并做机器检查；这不等于人眼全速观看及听感验收。样片供用户判断动作节奏和审美是否值得继续推广。

没有把本试验应用到其余信息卡，也没有覆盖原片、导入剪映或修改全片制作流程。
