# 单集制作与续做约定

生效日期：2026-10-09；2026-10-22 补充未来新集统一信息卡色板、语义动效选型结构检查和编码后检查，保留 v4.7 场景组修订。范围：V5 的读取、恢复、制作与验收；主干与工作树通过 Git 合并同步，以实际根入口及标准锁为准。

## 1. 当前依据与优先级

入口为根目录 `AGENTS.md` 和 `CURRENT_PROJECT.json`。后者指向当前标准及方法，不复制历史过程。新集采用当前指向的 v4.7 标准；续做旧集仍按本集锁定版本及本集明确覆盖，未经用户明确要求不迁移旧集。当前测试集的v4.6锁与单独demo覆盖不会因本轮更新被改写。

优先级：用户当前明确指令 > 本集已确认的覆盖项和样片 > 锁定标准中的品牌固定规范 > SOP 默认参数 > 工具默认值。本约定承接当前锁定标准，约束读取、恢复与阶段执行，不另设与该标准冲突的视觉要求，也不降低事实、声音或交付标准。

按下表分阶段读取有效标准。历史快照内“每次开始或恢复读取完整 SOP、全部提示词”的旧启动方式不覆盖此约定；旧快照保留原文和哈希。v4.7动画层采用完整静态插画硬切，单张连续≤2.0秒，非固定2秒切换；信息卡保留连续解释过程及阅读，不受2秒限制。两层取消固定角标，字幕独立固定底中。

本项目文件不能删除平台已经携带的历史上下文。可以在新对话中指向 V5 根目录和本集状态续做，无需主动检索旧聊天或复制整段历史。

## 2. 新集与续做

**新集**：在 `episodes/<新集名称>/` 建立独立目录，把 `CURRENT_PROJECT.standard.snapshot_root` 指向的标准目录复制到本集 `00_brief/standard_snapshot`，把 `standard.lock` 指向的锁复制到本集 `00_brief/standard_lock.json`；把 `templates/episode_state.json` 复制为本集状态，`project_root` 填本次实际工作根的绝对路径。以本集标准的 `production_standard/defaults.json` 为基础，合入本集明确覆盖，另存 `00_brief/effective_defaults.json`。将标准的 `production_standard/episode_contract_template.json` 复制到本集 `03_storyboard/production_contract.json`，在分镜中填完并设 `is_template=false`。记录输入路径、内容哈希、交付范围、参数来源和用户覆盖项，再按现有制作阶段推进。不要复制旧集全部产物与缓存。

本版标准清单内路径相对于标准目录。品牌参考图随本地标准保存，但不进入 Git；换机后需按 `production_standard/brand_assets.json` 恢复并核对哈希。外部风格参考见 `production_standard/visual_references.json`，只按阶段需要读取，不要求每集重看参考成片。开工完整性检查可运行 `python <本集标准目录>/production_standard/verify_standard.py`；它只校验标准配置和锁，不渲染或审查视频。

新集参数从锁定标准开始应用用户有效要求。上一集“不加音效”“不烧录字幕”、事实纠错方式或一次剪映导出授权，不自动变成新集默认。延续系列风格不等于沿用旧文案、工具数字、镜号和时长。

旧集 `prepare_episode.py`、`build_timeline.py` 及试验目录的 `prepare.py` 含特定内容或路径，不作为通用新集入口直接运行；需复用时先按新集适配相关部分。旧标准的 `start_episode.py`、`build_standard.py` 和 `verify_standard.py` 同样只服务其锁定版本，不运行它们覆盖新标准。复用实现时取消动画图内/镜头运动、动效转场和固定角标，消费动画 `max_static_seconds=2.0`；`target_static_seconds=null`表示没有统一目标时长，不能回退成固定2秒节拍。信息卡 `max_static_seconds=null` 表示不套动画上限。长语义段由有增量的多幅插画承接，不能只改最后的切点或补随机图。帧率、音频对齐、总片长、去重与解码检查保留。当前没有因此新增任意SRT一键通用生成器。

**续做**：读取本集状态、用户新要求和当前阶段必要文件，直接从 `next_action` 继续。若状态缺失，先从本集配置及准确指向的最近报告恢复一次，写入状态；不得重新搜索所有历史集或凭目录日期推测。

开始新集、切换正在制作的集或完成交付时更新根入口的 `latest_episode`；上一集结果保留在原目录。新集拥有状态文件后，根入口仅保留 id、root、state_file 和简短状态，避免复制两份动态明细。

事实、产品规格、授权条件等需要当前资料时，按本集涉及对象核实并保存来源。已有素材可在用途、有效期和内容未变化时复用；不每次重新开展整个 GitHub/X 资料调研。

分镜完成及时间轴/素材映射变化后，用本集锁定的检查器运行 `python <本集标准目录>/production_standard/validate_episode.py --episode-root <本集绝对路径>`。合同的主画面片段连续覆盖全片，逐段声明 `layer`、资产、起止帧、语义增量、配音锚点、差异维度及动效/转场；插画另填 `scene_id`、`scene_progress`，相对上一张插画换景时填 `scene_change_reason`（中间有卡片也照填）；口播字幕另列。同景ID可以回用，回场图像不能复用。相同文件字节即使换文件名或拆段，仍按一个连续插画累计；信息卡不受2秒上限。

分镜和审片共同查看单张、连续场景组、整段语义。连续同景必须有可见叙事推进，语义强相关本身不构成留景理由；跨情境可以承接同一主题，用人物、目标、关键道具或因果维持连贯。既不按每句强制换景，也不设固定场景时长或数量。检查器汇总场景组但不判断枯燥，只验证声明、时间与源资产身份，不能看懂插画、证明真实静止或代替试听。

实现阶段逐项核对有效参数的消费位置：读取了JSON不等于布局、配色、计时或角标开关已经生效。硬编码与本集要求不同的地方要显式适配并记录；对最终编码画面确认，而不只检查预览或源文件。开头样片需来自实际管线；不固定钩子秒数，也不为钩子改动锁定配音。

本次代码修订后建立的新集，渲染和已获明确要求的导出均从本集锁定的 `run_stage.py` 启动：

```powershell
python "<本集标准目录>/production_standard/run_stage.py" --episode-root "<本集绝对路径>" --stage render --entry "06_project/render.py" -- <本集脚本参数>
python "<本集标准目录>/production_standard/run_stage.py" --episode-root "<本集绝对路径>" --stage export --entry "<本集导出适配器.py>" -- <本集脚本参数>
```

`--entry` 是本集内实际存在、已完成适配的 Python 入口，不是待创建文件名；未提出剪映要求时不执行第二条。`--check-only` 只检查输入，不启动子脚本。入口核对两份标准锁、依赖哈希、本集合同和有效参数的核心约束、合同帧率；失败不启动脚本，成功后传递子脚本退出码。提供 `V5_EPISODE_ROOT`、`V5_EFFECTIVE_DEFAULTS`、`V5_PRODUCTION_CONTRACT`、`V5_STAGE` 四个绝对来源／阶段环境变量，适配器应读取它们，把相同配置传到实际 JavaScript／FFmpeg。记录参数消费位置；测试应改变实际输出相关参数，确认结果随之变化。这个入口不生成分镜，不保证渲染器使用了环境变量，也不检查画面像素或启动原生复检。手工绕过入口、直接执行旧脚本不受此检查覆盖。

旧集和本次修订前的锁定快照继续原入口；不要向旧快照补写该脚本或重算旧锁。当前新集剪映工具来源见根 `CURRENT_PROJECT.export_tooling`，固定使用仓库内 Skill；在创建本集导出适配器时将所需工具复制到本集并记录哈希，不默认引用全局已安装 Skill。旧交付的内置 `delivery_tools` 继续保留。只导出时执行必要结构检查；注册按本集要求调用，原生复检仅另获明确要求时传 `--require-native-evidence`。仓库更新不会自动安装全局 Skill。

### 3.1 信息卡动效选型与实现检查

从本次约定后新开展的信息卡设计按本节执行，不追溯改写旧集、旧分镜、标准快照或已有画面。制作代理负责检索、选型、适配和实现检查；用户反馈仍沿用已有样片流程，不新增人工选卡审批、逐卡确认或额外一轮审片。

**设计前检索**：先读完整语义段及配音时序，确定对象、对象关系、要解释的变化与阅读目标，再使用根 `CURRENT_PROJECT.research_resources.information_card_motion.query_tool` 检索本地候选。先读少量查询结果，按需打开候选 `cards/<id>.md`，适配时才读对应源码；不重读全库、不重新开展整库研究。关键词只是检索入口，选择必须符合整段含义、素材条件及本集锁定规则。

**逐卡记录**：优先并入本集 `episode_state.authoritative_files.semantic_design` 所指的设计文件，不另存重复配置。尚未建立设计文件时，在本集 `03_storyboard` 新建并登记该指针。库提交与来源路径可在该文件集中记一次；每张卡最少记录：

本次修订后新集从锁定标准的 `production_standard/semantic_design_template.json` 建立上述唯一设计记录，保留原有语义内容并填写机器可核对的 `cards` 条目，设 `is_template=false`。每卡用 `clip_ids` 对应合同片段，不用重复复制分镜；所有信息卡片段必须恰好被一个设计条目覆盖。`library` 记录本次查询的来源提交及实际 catalog SHA-256。渲染前 `run_stage.py` 调用锁定的 `validate_card_design.py` 检查覆盖、选择依据、配音锚点、源文件/函数和色板声明，缺项不启动。此时输出观察保持 `not_performed`，不要求尚未产生的成片证据。检查只证明结构完整，不证明读过候选、实现符合语义或画面通过。

| 内容 | 记录要求 |
|---|---|
| 卡片身份与语义 | `card_id`、对应时间轴片段 ID、完整语义段的对象关系 |
| 检索与选择 | 检索词或可定位的查询记录、实际读取的候选笔记、选用的配方 ID（组合使用可列多个）、选择理由 |
| 未采用库效果 | 配方 ID 留空，说明不适用原因及自行设计方案；允许自写过程或按既有规则使用有明确用途的静态卡，不强制套用 |
| 配音与预期过程 | 对应 SRT/配音时间锚点、动作应对齐的语义、关键中间状态与结果阅读保持 |
| 实现落点 | 实际源文件与组件/函数位置，采用或改写的过程及关键参数消费位置 |
| 输出观察 | 匹配版本的编码输出、时间或帧位置、可定位的画面证据、实际观察与检查状态 |

**实现后检查**：制作代理核对实际实现与编码画面的初态、中间过程、终态及必要过渡，确认对象身份、顺序、路径/到达、遮挡和阅读保持符合所选语义。只填写配方名称、读过文件、生成事件表或传入参数，均不能证明过程已经进入画面。发现不匹配时修复受影响实现，再检查相关输出；需要换方案时同步更新本集选型记录。

选型时先写一句“什么对象，由什么状态，经什么操作，变成什么状态”，再选择能表现这个过程的机制。例如比较可同步对照，展开可由堆叠变铺开，改写需在原对象上发生替换，回退需保留历史并出现恢复结果；这些是语义示例，不是每集必用菜单。线条用于表达确有的关系，不能以连线、淡入、换字或搬运小图标充当文案要求的具体操作。拒用候选要说明机制为何不合适或适配后仍有何具体限制，不能只写“不适合本集”；不为采用库效果歪曲语义，也不设配方数量或比例。

检查证据复用本次已有样片或输出检查中匹配版本的材料，不为选型另加人工确认或无变化的重复检查。对应证据挂本集既有 `checks`，关联依赖指纹、产物哈希及时间/帧位置；`information_card_process_and_reading` 按实际观察记录。结构检查、源码检查、关键帧观察、正常速度主观视听分别记状态，未执行不得写通过，也不把填表或机器检查算作实际语义验收。

本节补充动效执行步骤，配色另按§3.2；不改变插画静态硬切、字幕、声音或剪映分层导出要求，不引入上游整套制作规则。卡片形式与运动仍服务文案，库内效果没有固定使用数量或采用比例。

### 3.2 信息卡配色默认与落地检查

本次修订后建立的新集统一采用《闲鱼暗号》xianyu 色板：近黑绿背景 `#07110C`、浅绿强调 `#87EFAA`、米白文档 `#F1F3EB`，其余语义颜色角色见锁定 `defaults.json`。新集复制后，`00_brief/effective_defaults.json#cards.palette` 是实际渲染唯一颜色来源，且等于 `cards.palette_presets[cards.default_theme]`；默认主题为 `xianyu`。不能在场景代码按卡号或题材切换蓝色/浅纸主题，也不能以旁置 `card_palette.json` 的说明冒充有效配置。

统一配色只约束信息卡生成的图形界面；插画继续自然配色，真实截图和照片保留原色。卡内允许米白纸面、浅绿焦点、深绿表面、无框、证据放大及不同关系布局；不把统一色板变成统一双框或统一文件夹。深底配浅字，亮面配深字。只有本集用户明确覆盖才改变整集默认色板，并在 `episode_state.scoped_overrides` 登记 `field=cards.palette`、`scope=information_cards`、`reason`、`user_basis`；记录本身不能证明授权真实性。`paper/dark` 预设不再是自动轮换选项。

制作代理完成以下检查，复用现有样片与交付检查，用户不额外选卡或逐卡审批：

1. **实现与参数消费**：记录场景背景、面板、文字和强调色的实际消费位置；首次适配或相关代码变化时，用内存参数或临时副本改变一个实际色值，经实际场景入口确认输出随之变化。只读 JSON 或返回配置对象不算证据。正式配置不改，依赖相同的有效探针可复用。
2. **编码后配色**：逐卡检查最终编码输出的初、中、末态及关键变化，确认全片主题统一、局部对比可读，没有代码覆写的意外主题。压缩/抗锯齿容许色差，不要求每个视频像素与十六进制值完全相等，也不把真实素材原色算违规。
3. **编码后过程**：按 §3.1 逐卡对照语义动作与配方机制，观察真实初态、必要中间态、终态和配音落点；记录时间/帧位置、实际观察、源实现依赖及输出哈希。只填配方 ID、改变像素或通过结构检查不能算落实。过程缺失则修复受影响卡，更新对应证据。

在本集既有 `checks` 中登记证据；状态模板分列 `information_card_selection_coverage`、`information_card_palette_consumption`、`encoded_information_card_palette` 和已有 `information_card_process_and_reading`。正常速度整片视听仍单列，抽帧不代替播放。缺项、失败或过期证据不得标通过；可以按既有流程交付明确标注待检项的样片，不能称“已按规范全部验收”。仅作用于未来新集，不改旧集锁或已有画面。

## 4. 限制重复读取和检查

- 先明确本次要处理的集和文件。搜索限制在本集当前阶段的目录，排除根入口列出的历史与缓存位置；需要某一修订或参考时直接访问准确路径。
- 输入、规则、脚本、字体、依赖/工具版本、素材、渲染参数构成对应产物的依赖记录。时间戳只能辅助定位，不能代替内容指纹。程序在本地比较，返回变化清单和异常，不把清单全部送入对话。
- 验证状态须同时关联依赖指纹、产物哈希与证据路径。依赖或产物变化后，将受影响检查标为 `stale`。没有完整依赖记录的旧检查可作为历史证据，不能直接标成“已复用通过”。
- 小改动跑一次覆盖该改动的必要验证；渲染输出变化后检查对应新输出。全新成片仍执行适用的交付检查。失败、再次修改、影响扩大或用户明确要求时才重复。
- 不因用户一句“继续”重新检查整套标准、全盘素材、所有 ZIP 或编辑器注册；也不因节省读取而跳过真正受影响的检查。
- 使用长时间本地程序时保留日志，摘要反馈结果，不按帧持续向模型输出。大文件先提取所需字段、章节或错误附近内容。
- 日常制作不附带系统改造。非阻塞改进记入本集 `deferred_improvements`，待明确开展优化时处理。确有收益才并行委派，任务之间避免重叠读取。

## 5. 状态维护与验收边界

`episode_state.json` 是交接记录，不替代 `episode.json`、`effective_defaults.json`、分镜或渲染配置。状态只指向这些内容的准确路径，不让两份配置互相覆盖。

状态更新时间点：输入/要求确定、每阶段完成、修改使证据失效、发生失败、交付或需要交接。每次只维护当前要求、采用版本、已完成阶段、产物、证据、问题和下一步；不追加聊天全文和逐条工具日志。

状态中的 `rule_reads` 记录执行来源，不能替代新上下文对必要规则的读取。完整视听、原生编辑器打开/播放/导出分别记录，没有证据则为 `not_performed` 或 `not_recorded`。草稿已注册不等于剪映已打开验收。

信息卡设计交接时，通过 `authoritative_files.semantic_design` 定位 §3.1 的逐卡选型与实现记录；对应输出观察在既有 `checks` 留证。状态只登记路径和实际状态，不复制整份候选库或选型正文，不把制作代理自检改成待用户选卡审批。

失败时记录失败步骤、受影响文件、有效旧产物和恢复动作；未通过的临时文件不得替换交接记录中的有效交付路径。

默认交付继续按本集约定。用户明确要求剪映分层输出时才加载对应 skill 和适配器；只在需要编辑、重新导出或排错时读取 `09_revisions`。已有导入回执优先于早期 README 的旧状态，但回执不证明当前编辑器内已播放通过。
