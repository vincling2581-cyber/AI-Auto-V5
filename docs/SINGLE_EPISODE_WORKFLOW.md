# 单集制作与续做约定

生效日期：2026-10-09。范围：V5 项目内的读取、恢复、验证和状态维护。授权依据：用户要求规范单集制作，避免每次查看过时对话和内容。

## 1. 当前依据与优先级

入口为根目录 `AGENTS.md` 和 `CURRENT_PROJECT.json`。后者指向当前标准及方法，不复制历史过程。制作内容仍遵守锁定的 v4.5 标准与用户已采用的增强信息卡方式。

优先级：用户当前明确指令 > 本集已确认的覆盖项和样片 > 锁定标准中的品牌固定规范 > SOP 默认参数 > 工具默认值。本约定只调整读取与恢复方式，不降低画面、事实、声音或交付标准。

标准快照内“每次开始或恢复读取完整 SOP、全部提示词”的旧启动方式，在 V5 日常执行中按本次用户要求改为下表的阶段读取。快照保留原文和哈希，不改写历史文件。标准规则本身依然有效；有冲突或缺少必要信息时读取对应原文。

本项目文件不能删除平台已经携带的历史上下文。可以在新对话中指向 V5 根目录和本集状态续做，无需主动检索旧聊天或复制整段历史。

## 2. 新集与续做

**新集**：在 `episodes/<新集名称>/` 建立独立目录，复制当前有效标准快照和锁；把 `templates/episode_state.json` 复制为本集 `00_brief/episode_state.json`。记录输入路径、内容哈希、交付范围、参数来源和用户覆盖项，再按现有制作阶段推进。不要复制旧集全部产物与缓存。

新集参数从锁定标准开始应用用户有效要求。上一集“不加音效”“不烧录字幕”、事实纠错方式或一次剪映导出授权，不自动变成新集默认。延续系列风格不等于沿用旧文案、工具数字、镜号和时长。

旧集 `prepare_episode.py`、`build_timeline.py` 及试验目录的 `prepare.py` 含特定内容或路径，不作为通用新集入口直接运行；需复用时先按新集适配相关部分。当前没有因此新增或承诺一键通用生成器。

**续做**：读取本集状态、用户新要求和当前阶段必要文件，直接从 `next_action` 继续。若状态缺失，先从本集配置及准确指向的最近报告恢复一次，写入状态；不得重新搜索所有历史集或凭目录日期推测。

开始新集、切换正在制作的集或完成交付时更新根入口的 `latest_episode`；上一集结果保留在原目录。新集拥有状态文件后，根入口仅保留 id、root、state_file 和简短状态，避免复制两份动态明细。

## 3. 按阶段加载有效内容

表内 SOP 节号与 P 编号均相对于本集锁定的标准快照。标准变更后核对路由，不能机械套用旧节号。首次执行某阶段且当前上下文缺少其规则时读取；同一上下文已有且未变化时直接使用。可从 `rules.json` 按类别提取当前有效条目，不读取同一规则的多个重复版本。

| 阶段 | 所需内容 | 保留的检查 |
|---|---|---|
| 开工 | 本集输入/覆盖项；标准入口及锁；SOP §0–1、§9；P01；默认参数中本集适用字段 | 输入存在、声音/字幕时长、版本、交付范围；本集初始化时核对锁定文件完整性，报告只输出摘要 |
| 分镜与信息卡内容 | 本集 SRT、声音时序；SOP §2–3、§4.1–4.2、§6、§8；P02–P04、P09；本集事实资料 | 文案对应、信息层次、事实条件、阅读时间；用户分镜表沿用五列 |
| 插画与人物动作 | 本集图单与已采用角色参考；SOP §2、§4.2–4.4、§5；P03、P06–P09 | 人物身份/眼部/肢体归属、明显动作、场景下沿、去重及动画层状态时长 |
| 信息卡实现 | 本集语义设计与事件；SOP §4.5、§6；P04–P05、P09；只读所用场景/组件 | 对象连续运动与中间态、到达/遮挡、容器内文字边界、停留阅读；不将人物层 2.8 秒目标套成卡片阅读上限 |
| 声音与合成 | 本集配音、事件、输出参数；SOP §7、§8.3；P10 | 原声处理约定、音画同步、实际轨道、帧率/分辨率/时长/解码；只启用获授权的声音项 |
| 交付 | 本集变更、准确指向的报告和产物；SOP §11–12；P11–P12 | 适用质检条目、要求的可编辑性；交付包在内容固定后校验；主观视听和原生编辑器状态如实记录 |
| 局部修改/恢复 | 本集状态、变更范围、涉及的代码/素材；SOP §9.2、§10.3–10.4；P13–P14 | 受影响项目和必要下游检查；其余有效证据不重复生成 |

事实、产品规格、授权条件等需要当前资料时，按本集涉及对象核实并保存来源。已有素材可在用途、有效期和内容未变化时复用；不每次重新开展整个 GitHub/X 资料调研。

## 4. 限制重复读取和检查

- 先明确本次要处理的集和文件。搜索限制在本集当前阶段的目录，排除根入口列出的历史与缓存位置；需要某一修订或参考时直接访问准确路径。
- 输入、规则、脚本、字体、依赖/工具版本、素材、渲染参数构成对应产物的依赖记录。时间戳只能辅助定位，不能代替内容指纹。程序在本地比较，返回变化清单和异常，不把清单全部送入对话。
- 验证状态须同时关联依赖指纹、产物哈希与证据路径。依赖或产物变化后，将受影响检查标为 `stale`。没有完整依赖记录的旧检查可作为历史证据，不能直接标成“已复用通过”。
- 小改动跑一次覆盖该改动的必要验证；渲染输出变化后检查对应新输出。全新成片仍执行适用的交付检查。失败、再次修改、影响扩大或用户明确要求时才重复。
- 不因用户一句“继续”重新检查整套标准、全盘素材、所有 ZIP 或编辑器注册；也不因节省读取而跳过真正受影响的检查。
- 使用长时间本地程序时保留日志，摘要反馈结果，不按帧持续向模型输出。大文件先提取所需字段、章节或错误附近内容。
- 日常制作不附带系统改造。非阻塞改进记入本集 `deferred_improvements`，待明确开展优化时处理。确有收益才并行委派，任务之间避免重叠读取。

## 5. 状态维护与验收边界

`episode_state.json` 是交接记录，不替代 `episode.json`、`effective_defaults.json`、分镜或渲染配置。状态只指向这些内容的准确路径，不让两份配置互相覆盖。

状态更新时间点：输入/要求确定、每阶段完成、修改使证据失效、发生失败、交付或需要交接。每次只维护当前要求、采用版本、已完成阶段、产物、证据、问题和下一步；不追加聊天全文和逐条工具日志。

状态中的 `rule_reads` 记录执行来源，不能替代新上下文对必要规则的读取。完整视听、原生编辑器打开/播放/导出分别记录，没有证据则为 `not_performed` 或 `not_recorded`。草稿已注册不等于剪映已打开验收。

失败时记录失败步骤、受影响文件、有效旧产物和恢复动作；未通过的临时文件不得替换交接记录中的有效交付路径。

默认交付继续按本集约定。用户明确要求剪映分层输出时才加载对应 skill 和适配器；只在需要编辑、重新导出或排错时读取 `09_revisions`。已有导入回执优先于早期 README 的旧状态，但回执不证明当前编辑器内已播放通过。
